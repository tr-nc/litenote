# 单张横线纸：实现与验证

## 当前合同

只编辑一份固定横线纸。没有工具盘、待办 UI、拖出创建、文档列表、新建／删除文档入口。⌘A 先选空行分隔的当前段，再按一次选全文；⌘A → ⌘A → Delete 用于清空正文；关闭按钮与 Esc 只隐藏，快捷键重新显示同一个编辑器。

旧多文档、待办布局、永久删除等历史证据移至 [VALIDATION-HISTORY.md](VALIDATION-HISTORY.md)，不再作为当前行为约定。

## 实现边界与数据安全

- `NoteStore.loadPaper()` 是固定文档身份的所有者：首次读取旧文件，按横线纸文件修改时间选择最近一份，没有则保存一份空白横线纸；正文存在后才原子写入 `paper.json` 身份引用。旧文件不删除、不合并、不转换。
- 后续启动只读取被引用的那一份，不按最近修改时间重新选择，不依赖 UserDefaults 判断文档身份。手动清空后仍保存同一 UUID，旧文档不会复活。
- 损坏／缺失的引用或固定正文会阻止打开并报告错误，不退回其他文档或创建空白替代。首次迁移遇到坏旧文件时也不写入引用；已固定文档之后，其他未打开的旧文件不再参与启动。
- `PaperWorkspace` 只持有一个 `let note`，不再有集合、add/remove、聚焦文档 ID 或创建回调。快捷键、菜单、Esc、关闭按钮共用显隐路径；隐藏前提交输入法组合并保存，导入中／保存失败时保持窗口。
- `NoteController` 拒绝打开旧 checklist 内容。待办布局、checkbox、任务拆分／合并、工具盘和创建拖动代码均已删除；旧 checklist JSON 类型仅用于识别和保留旧数据。
- `NoteController` 持有权威正文，TextKit 2 只是编辑投影。撤销／重做后同步正文；清空是正常文本编辑，可以在当前会话中撤销。未新增删除实体文档或附件的 API。
- 保留固定白字、深色系统毛玻璃和颗粒。正文／光标／横线共享最小 25pt 行盒，不限制最大行高；装饰层不承担输入、数据或撤销职责。
- 附件先导入为独立 PNG、验证落盘后再插入正文。复制仅发布文字与绝对路径。清空／剪切不会删除已导出的图片文件。
- 旧快捷键持久化名称 `toggleTray` 保留，仅代码名和 UI 改为横线纸，避免重置用户绑定。触发时机使用 KeyboardShortcuts 的 `onKeyDown`，按下即显隐，不等待松手；未增加输入监控或权限。窗口位置和显隐偏好沿用旧键。

## 自动化证据

最新完整 XCTest：**76 项全部通过**，包括此前被桌面锁屏阻挡的窗口焦点测试。此前 `ioreg` 确认锁屏期间无法获得 key window；未修改或弱化该断言，本次完整运行已通过。全局快捷键的真实按下／松开及长按行为仍需按下方手工清单确认。环境：arm64、macOS 26.6.2、Xcode 27.1、macOS 27 SDK。测试使用临时数据目录、独立 UserDefaults suite 和命名剪贴板，不读取用户正文、不注册全局快捷键；窗口测试会短暂显示测试窗口。

覆盖：

- 首次启动只创建一份横线纸，重复读取和重新创建 store 后身份不变。
- 多旧文档迁移按修改时间而非创建时间选择横线纸，所有原文件逐字节保留；只有旧待办时创建一份新空白横线纸。
- 迁移后的图片仍可显示、复制实际路径、继续编辑与保存；后来修改其他旧文件不会切换固定文档。
- 缺失／损坏／未来版本正文、坏引用、迁移失败不被空白覆盖；已经固定后，无关旧坏文件不阻塞启动。
- 清空文字和图片后重载仍为空、UUID 不变；当前会话可撤销清空，图片路径继续存在。
- 关闭按钮保存并隐藏，原内容和备份保留；保存失败不隐藏，恢复存储后可重试。快捷键路径多次 toggle 保留同一窗口、正文、位置、选区，无工具盘或额外纸张。
- 唤出后恢复 first responder，通过真实窗口发送键盘事件可在原选区续写。菜单不含创建、删除或文档列表，待办内容不能创建编辑窗口。
- 原生 TextKit 2 长正文、普通换行、全选删除／撤销／重做、部分复制、图片导入／剪切、旧颜色元数据 round-trip、附件缺失保护、原子保存和备份。
- 两层 ⌘A 的 10 项测试经真实编辑器与 NSMenu key equivalent 覆盖当前段→全文、重复全选、移动光标／编辑后重新选段、已有选区、空行与首尾边界、纯空白文档、CRLF／Unicode 换行、中英文／emoji、视觉折行／缩放、图片路径复制，以及选段删除／撤销不改其他段和附件。选择操作不修改正文或文档 revision。
- 输入法协议：拼音更新、候选提交、组合区内部光标、显式／隐式替换范围、emoji 的 UTF-16 范围、连续确认与保存期间不提交临时组合文本。
- 横线实际绘制像素与文字基线对齐：中英文、空行、末字删除、连续空行重载、撤销／重做、换行、滚动、缩放和非整行高图片。
- 毛玻璃设置持久化／重置／范围校验，已有和新建视图同步；确定性颗粒绘制、尺寸／强度变化、不抢输入及不透明回退。窗口无显隐动画，标题文字隐藏，关闭按钮保留。
- 屏幕几何约束覆盖负坐标、上下排列显示器及超大窗口在断屏后保持可达。

旧工具盘／待办专属测试已随功能退役移除，通用编辑、附件、输入法、存储和外观回归保留；测试总数不与历史版本直接比较。

## 缩放时颗粒纹理游动修复

- **影响范围：** 自绘颗粒在拖动底边时跟随底边移动，原有纸面区域发生纹理滑动；左边及相应角落具有同类风险。真实 NSWindow 缩放的像素测试中，底边调整失败，而顶边调整、整窗移动原本通过。这里固定的是自绘颗粒，不是锁定系统毛玻璃背后的桌面图像。
- **根因：** 原实现用 NSColor pattern 的默认绘图原点，等价于把颗粒锚在窗口左下角。底边缩放改变这个原点，但没有补偿纹理坐标；实验确认同一窗口局部坐标的像素完全相同、原有纸面位置的像素变化，因此不是噪点重新生成或被拉伸。只补 patternPhase 还不足以保证不同绘图区域／非整数粒径的离屏重绘一致。
- **引入时间：** 毛玻璃首次实现 `3fecf8b`（2026-10-29）引入默认 pattern 平铺；之前没有该颗粒层。
- **干净修复：** GlassTexture 独占持久的纸面局部纹理原点和窗口几何快照。尺寸变化时补偿窗口原点位移；整窗移动只更新快照、不改变纹理原点。live resize 中兼容分开送达的移动／缩放通知，并在绘制前同步，避免依赖通知和重绘顺序。用同一缓存 CGImage 在明确的局部网格上按需平铺，局部重绘也使用相同 tile 矩形；不拉伸纹理、不用屏幕坐标生成噪点、不创建全屏位图或 timer，不改文本／光标坐标。
- **验证：** 新增 9 项像素级回归：底边、顶边、整窗移动、四边／四角、五档粒径（含默认 0.7 和其他非整数值）、连续缩放再还原、隐藏时移动并继续缩放、局部／整页重绘一致、单设备像素步进、扩张区域的平铺连续性、关闭颗粒／减少透明度期间仍保留纹理坐标。底边测试在修复前确实失败，修复后上述全部通过。测试经过真实 NSWindow.setFrame、窗口通知与 GlassTexture.draw，不只断言偏移变量。
- **边界：** 测试覆盖程序化窗口几何变化及当前显示器的实际 backing scale；未自动驱动鼠标抓住窗口边框。真实拖边过程、系统合成器的瞬态画面和跨 Retina／非 Retina 屏仍需解锁后手工确认。系统毛玻璃采样桌面的变化仍由 AppKit 管理。

## 图片剪贴板的粘贴命令被禁用

- **影响范围：** 剪贴板只有 PNG/TIFF 位图时，系统“粘贴”菜单可能灰掉，⌘V 被菜单层消耗但未进入图片导入。直接调用 `paste` 的原测试仍通过，因此未覆盖实际命令入口。现场只读取了系统剪贴板的格式列表，确认有 PNG/TIFF；未读取其图片内容，也未改写系统剪贴板。
- **根因：** 编辑器设置 `importsGraphics = false` 来避免原生图片导入绕过 AttachmentStore，但自定义 `paste` 支持位图。继承的 NSTextView 菜单校验仍按原生导入能力判断，在执行自定义 paste 之前禁用了命令。只读诊断确认同一图片剪贴板下，原生校验在 importsGraphics=false 时返回 false、true 时返回 true；实际菜单回归在修复前也失败。
- **引入时间：** `importsGraphics = false` 与自定义导入始于 `f2a3dcc`（2026-10-28）；原实现没有配套的菜单校验覆盖。这不是切换到快捷键按下事件时删除了图片功能。
- **干净修复：** NoteTextView 为 paste／pasteAsPlainText／pasteAsRichText 统一校验可编辑状态、导入状态和自定义导入支持的 PNG/TIFF/文本格式。菜单更新仅检查可用格式，不读取或解码负载。图片类型优先级与导入共享定义；仍保持 importsGraphics=false，仍先验证附件落盘再提交正文。不启用任意文件或原生富文本导入；富文本剪贴板提供的纯文本表示仍按普通文字粘贴。
- **验证：** 新增 4 项回归：通过真实 NSMenu.update 和 Command-V key equivalent 分别导入仅含 PNG／TIFF 的命名剪贴板；三个粘贴命令的格式／空剪贴板／只读状态校验；导入中禁用及完成后重新启用、防止重复提交；富文本的纯文本表示不带入字体／颜色。修复前的菜单测试明确失败，修复后完整 64 项通过。图片数据导入、路径复制和缺失附件保护的旧测试继续保留。

## 构建与截图边界

Release 为 arm64 + x86_64 通用构建，使用本地 ad-hoc 签名。构建／测试命令见 [README](../README.md)。没有在 Intel 硬件或 macOS 14 上运行验证；未做公证或公开分发。

XCTest 中的纸面截图是视图绘制缓存，可以验证文字、横线、颗粒和控件绘制；不是 WindowServer 的跨窗口实时合成截图，不能用来证明真实桌面背景模糊已完成视觉验收。

## 待手工验收

1. 正常退出旧版本后打开新 Release，确认没有右上角工具盘、只有选定的横线纸；当前内容、图片和位置与迁移约定一致。
2. 在其他应用里按 ⌥.，确认按下时即显隐、松开不再触发；长按不反复切换。反复隐藏／显示并直接续写；实际录制／清除／恢复快捷键，检查冲突反馈。
3. 点击关闭、Esc、正常退出后再启动：内容不丢、不会创建第二张纸。在有空行分隔的多段正文中验证 ⌘A 先选当前段、再次选全文；移动光标后重新选段。复制／删除当前段不影响其他段；两次 ⌘A 后清空全文，重启仍为空，不重新带回旧文档。
4. 实际中文输入法候选、组合取消、空格／Return 选词；真实截图粘贴 → 复制图片路径 → Pi 读取的完整链路。
5. 多屏移动／断屏、普通 Space、全屏应用和 Stage Manager；窗口层级与焦点策略仍需实际环境确认。
6. 明暗／高对比桌面背景下的三种系统材质、颜色选择器和滑杆；系统“减少透明度”动态切换、不同缩放比例、失焦后文字清晰度。实际拖四边／四角时，已有区域颗粒应不游动；再拖整张纸时颗粒应跟随窗口，而不是停在桌面上。
7. VoiceOver、登录启动批准流程，空闲 CPU／内存和输入响应实测。

## 仍存在的限制

正文写入在主线程经 400ms 合并后同步执行，图片显示解码也可能占用主线程；超长正文、大图和突然断电场景未完成专项验证。暂无备份恢复 UI、附件自动清理、文件拖放、富文本导入、图片尺寸编辑或跨设备同步。原始图片粘贴限单帧 PNG/TIFF、50 MB／4000 万像素以内。
