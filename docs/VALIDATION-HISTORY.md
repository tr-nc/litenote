## 关键实现约束

- `NoteController` 持有权威 NoteDocument；TextKit 负责编辑投影。
- `PaperWorkspace` 是纸张集合与可见性的唯一所有者；快捷键、菜单、重开应用和 Esc 都通过它路由，不分别对各窗口取反。整体隐藏前先保存全部纸张，失败时保留整个工作区可见。
- 所有已提交编辑、undo/redo 都进入相同的模型同步入口；保存前再次同步，避免撤销后写回旧模型。
- 测试确认原生 undo 会恢复 NSTextStorage，但某些路径不立即回调 `textDidChange`；因此在 UndoManager 完成事务通知上同步，且内容相同不增加 revision。
- `ChecklistDocumentView` 按稳定 Task ID 持有区域左栏 checkbox，不依赖 TextKit 的临时附件视图。正文保留零宽语义标记，统一选择/复制/拆分语义不变；区域边框、横线和控制位置从实际 TextKit 布局派生，不另存第二份正文或 checked 状态。
- 勾选使用明确的语义撤销事务，替换对应标记并进入相同的文档同步入口，不再伪装成一次原生附件键入；长内容、图片和段落重排后也能一次撤销勾选。
- 一份 NSTextView 容纳所有项目，不使用每项独立的 TextField/滚动框。不读取旧 `layoutManager`；测试确认 TextKit 2 仍有效。
- AttachmentStore 独占图片导入，没有删除 API。ImageIO 工作在 actor 上，缩略图与实体原图分离；导入期间禁用正文编辑，关闭/退出会要求等待，正文意外变化时拒绝用过期选区插入。
- NoteStore 是串行正文写入者，原子替换、保留备份、拒绝旧 revision；无效正文不会静默转空白。
- 只在显式粘贴时读取剪贴板，不导入任意文件 URL；外部/原生富文本 drop 被禁用，避免绕开附件提交边界。
- 工具盘采用事件驱动 mouseDown / mouseDragged / mouseUp 状态机，无忙循环或全局输入权限。

## 已知限制 / 阶段 B 工作

- 没有自动备份恢复界面；坏文件只隔离拒绝载入并提示，保留原文件与备份。按用户新要求，删除是永久删除，不提供废纸篓。
- JSON 保存经过 400 ms 合并，但仍在主线程同步写入；载入和显示缩略图也可能阻塞。待办区域重排目前请求完整文档布局，以确定连续区域边界；超长文档的输入性能还需专项测量。没有把大文档性能或突然断电最后按键不丢作为已兑现保证。
- 图片导入接受单帧 PNG/TIFF 剪贴板数据，最大 50 MB / 4000 万像素；文件 URL、动画、多页图和任意富文本会明确拒绝。无图片显示尺寸编辑 UI。
- 无私有剪贴板结构类型；应用内复制粘贴目前也走 Pi 纯文本表示。
- 普通 Backspace/Delete、全选替换、跨项删除有测试；更多原生文字命令、IME、Services 和辅助技术输入仍需真实验证。
- KeyboardShortcuts 的 recorder 提供系统/菜单冲突提示；本机没有穷尽验证其他应用占用或 Carbon 注册失败的反馈，尚不能宣称所有冲突都可见。
- 窗口布局暂存 UserDefaults 的全局 frame，断屏时重新约束；尚未按稳定显示器标识建立独立工作区。
- 纸面包含底色/横线、待办区域边框和独立 checkbox，装饰随正文滚动，不强制量化图片高度。已有深色原生毛玻璃和静态颗粒；不播放窗口动画，资源性能指标和最终视觉定稿仍未验收。

## 横线与文字对齐修复

- **影响范围：** 横线纸的装饰线与文字错位，首行不对齐且后续行继续漂移；待办纸不绘制横线，不受这一问题影响。
- **引入时间：** 初始实现提交 `f2a3dcc`（2026-10-28）。当时以固定 `16 + 28n` 绘制背景，没有连接真实文字排版。
- **根因与复现：** 用户截图的两行中英混排在 TextKit 中的基线是 31、56pt，而旧背景线在 16、44、72pt……；既有起点错误，也有 28pt 网格与实际 25pt 行距不一致。原代码的像素回归测试失败，距应有书写线分别偏离 9.75、12.75pt。
- **修复：** RuledPaper 读取可见 TextKit 2 layout/line fragment，横线统一位于实际字形基线下 3pt；只有正文末尾的空白区域延续输入行距，该行距由相同正文样式在 TextKit 中测量，不另造固定网格。图片所在行自然增高，不在图片区域铺满横线，也不修改文档/字体来凑格子。
- **重绘与证据：** 输入、换行、窗口 reflow 和原生撤销触发装饰重绘。新增 4 项实际原生视图像素测试，检查缺失/多余横线，容差 0.75pt；全部 27 项测试通过。已查看混排、窄窗滚动和插图的修复后截图。原始截图文本对应的最小回归命令：

```sh
xcodebuild -project Papertray.xcodeproj -scheme Papertray \
  -configuration Debug -destination 'platform=macOS,arch=arm64' \
  -derivedDataPath build test \
  -only-testing:PapertrayTests/EditorAndStorageTests/testRuledPaperRulesAlignWithMixedChineseAndLatinText
```

这些测试包含真实文字排版和绘制，但不代替实际中文输入法候选窗口的手工验证；没有宣称 macOS 14 已通过运行测试。

## 待办 checkbox 消失与区域布局修复

- **影响范围：** 新建空待办的 checkbox 首次显示不可见，改变选区后又出现；数据中的 Task ID/checked 状态并未消失。原先的长正文按钮测试没有覆盖空白项，不能证明创建路径可靠。
- **引入时间：** 初始实现 `f2a3dcc`（2026-10-28）让交互控件依赖 TextKit 附件 provider 的生成/回收。对齐横线的提交没有改变这一控件策略。
- **复现证据：** `testEmptyChecklistCheckboxSurvivesSelectionMoveAndReopen` 在原实现首次显示时测到 0 个 checkbox（应为 1）；后续仅变化选区就出现。框架内部未生成 provider 的具体原因未进一步归因，但“有语义标记却没有交互控件”的所有权缺陷已确认。
- **修复设计：** 每项是独立的可增高横线区域；保留一个 NSTextView，左侧控制由滚动文档视图按 Task ID 持有，右侧正文自然换行/增高，后续区域顺延。控件不随附件虚拟化或正文选区消失。装饰层只接收 checkbox 命中，其余指针交给正文。空区域同样有 checkbox 和书写线。
- **相邻边界和撤销：** Backspace/Delete 或选区替换删除项间分隔时，同时合并任务标记，避免两个区域落到同一行；勾选通过显式语义 undo/redo 更新相同模型。
- **兼容与验证：** JSON schema、Task ID、正文和附件路径不变，已有笔记直接使用新呈现。新增 5 项区域/交互测试，全部 32 项测试通过；检查了 `checklist-regions` 实际绘制截图。界面测试用非 key 显示窗口，避免从用户正在使用的应用抢走输入。真实 VoiceOver 和中文 IME 候选流程仍属于手工验收。

## 纸张与工具盘整体切换

- 快捷键保持 `⌥.`，沿用原来的快捷键持久化名称，不重置用户绑定。设置、菜单和 reopen 路由到同一个 PaperWorkspace。
- 显示时带出所有现存纸张和工具盘；只根据鼠标屏幕重新定位工具盘，不搬动纸张、清空内容或重置选区。创建、选择笔色不再隐藏工具盘。
- 普通 Esc 请求整体隐藏；原生关闭按钮/关闭窗口命令立即删除当前纸张。拖动中的 Esc 仅取消当前创建手势，便笺/输入法的按键不会被工具盘全局本地 monitor 抢走。
- 整体可见性持久化为 `workspaceVisible`，首次读取兼容旧版逐纸张可见性。单篇永久删除移出工作区并清除布局记录，其他纸张保持可见。
- 隐藏前统一 flush，失败不发生一半窗口隐藏。设置窗口不属于纸张工作区。
- 新增 7 项真实窗口/控制器测试，完整 43 项通过；快捷键系统事件、多屏与跨 Space 的手工验证仍需按上面的清单执行。

## 禁用窗口显隐动画

- 之前没有自定义过渡代码，但窗口的 `animationBehavior` 是 `.default`，会由 AppKit 推断并播放 `orderFront/orderOut` 动画；修改前新增测试确认工具盘、两种便笺和预览均是默认值。
- 工具盘/便笺共用的 NotePanel 在初始化时设置 `.none`，覆盖首次显示、重开和整体 toggle；拖动预览及设置窗口也在第一次显示前关闭自动窗口动画。不修改系统偏好，不加入延迟、淡入淡出或缩放过渡。
- 两项新增测试验证首次展示前、重复显隐以及拖动预览的窗口策略，完整 45 项通过。此验证不等于实测唤出延迟，也不声称控制 macOS 自己的 Space 切换或系统确认 sheet 动画。

## 原生红色删除入口

- 使用窗口已有的标准 close button，位置和外观由 AppKit 管理；通过 window delegate 立即永久删除，不显示确认 sheet。删除失败仍报告错误并保留窗口，可再次点击重试。
- Esc 改用独立的隐藏回调，不再调用会触发原生关闭按钮的 `performClose`，避免把收起操作变成删除请求。
- 测试验证原生按钮可见、启用且位于左上角，黄色/绿色按钮隐藏且无自定义标题栏附件；覆盖无确认立即删除、从工作区移除且不影响其他纸张、删除失败保留窗口并可重试，以及 Esc 只隐藏不删除。
- 完整 45 项 XCTest 通过，Release 通用构建通过；尚未手工验收不同系统外观下的红色按钮显示。

## 工具盘笔色显示修复

- **影响范围：** 工具盘五个笔色按钮的圆点显示为系统默认文字色，无法从外观识别笔色；浅色和深色模式、选中和未选中状态均受影响。笔色数据和点击回调没有改变。
- **根因：** 圆点使用按钮 title 的文字字符，`.regularSquare` 按钮的 `contentTintColor` 没有为这些文字着色。修复前通过真实按钮的绘制缓存比对笔色，50 组颜色/选择/外观组合全部失败。
- **引入时间：** 初始实现 `f2a3dcc`（2026-10-28）已采用上述 tint 与普通 title 组合。
- **修复：** ToolTrayController 在统一的选中状态更新中设置 attributedTitle 的前景色和字体，直接使用编辑器同一份 Ink.color；保留原来的选中圆环、原生按钮交互和无障碍状态。
- **验证：** 新增实际绘制测试覆盖初始展示、依次选择所有笔色、浅色/深色外观，并检查点击回调和选中标记。期望色块与按钮通过相同显示色彩配置渲染，避免把显示器色彩转换误判为色值错误。完整 46 项 XCTest 和 Release 通用构建通过。未验证其他 macOS 版本的运行表现。

## 快捷键恢复上次纸张焦点

- PaperWorkspace 统一持有本次运行中最后聚焦的纸张；快捷键 toggle、菜单和 reopen 使用同一显示入口。显式选择的纸张优先，其次是上次纸张，再次是最新创建的现存纸张；无纸张时才聚焦工具盘。选色也复用这一记录，不再由 AppCoordinator 单独维护另一份。

## 拼音确认后残留组合文本修复

- **影响范围：** 横线纸和待办纸中，输入法提交候选词时若未显式指定 replacementRange，原拼音会残留。例如通过真实 NSTextInputClient 接口依次调用 `setMarkedText("ce'shi", …)` 和 `insertText("测试", replacementRange: NSNotFound)`，修复前两种纸张均得到 `ce'shi测试`。普通无组合区输入和显式替换范围不受该原因影响。
- **根因：** NoteTextView 的 insertText 覆写把所有 NSNotFound 范围解析成 selectedRange；组合输入期间选区只是拼音内部的光标/选区，并非完整 markedRange。结果是候选汉字插入光标处，而非替换拼音。数据保存不是重复文本的来源。
- **引入时间：** `git blame` 确认该范围转换来自初始实现 `f2a3dcc`（2026-10-28）。
- **修复：** 在输入边界按原生语义解析范围：显式范围优先；未指定范围时，有组合文本则使用 markedRange，否则使用 selectedRange。之后仍走原有 checklist 结构保护和原生 NSTextView 插入，不扫描或删除正文中的拉丁字符。
- **验证：** 新增 4 项测试覆盖两种纸张、更新中的拼音、组合区内部光标、已有选区替换、emoji 前缀的 UTF-16 范围、普通/属性文本候选、显式替换范围、连续确认、确认后空格/英文输入，以及保存期间不提交临时拼音。完整 53 项 XCTest（包括此前受锁屏阻挡的 3 项焦点测试）和 Release 通用构建通过。测试复现的是输入法调用编辑器的提交协议，未自动驱动系统拼音候选窗口，真实输入法空格选词仍需手工确认。

## 深色毛玻璃与固定白字

- **范围：** 纸张、工具盘、拖动预览使用同一 GlassSurface；工具盘移除笔色按钮并缩短高度。标题栏保留原生删除入口，材质延伸到标题栏，但编辑器约束在 contentLayoutGuide 内，不覆盖标题栏。设置窗口继续使用原生表单。
- **所有权：** GlassPreferences 是外观设置的唯一持久化所有者，写入独立的 `glassStyle.v1` UserDefaults 键。设置实时发布给已有、隐藏和新建的表面，不触碰 NoteDocument、选区、焦点或撤销栈。旧 `ink` 偏好被忽略。
- **渲染：** 公开的 NSVisualEffectView / behindWindow / darkAqua 提供系统材质；编辑器和控件是材质的兄弟视图，避免 vibrancy 改写白字或图片颜色。Tint 以深色呈现，颗粒使用共享的确定性噪点图及按粒径缓存的 pattern，不用 timer、屏幕捕获、私有 blur API 或 Metal。浮动窗口失焦仍保持材质。
- **兼容：** 所有正文显示白色，旧文档的 Ink 字段仍可读取并无损保存；新输入使用原 schema 默认元数据。颜色规范化不改变图片附件。系统“减少透明度”启用时隐藏模糊层、使用不透明深色并关闭颗粒，运行期间监听其变化。
- **自动化：** 完整 59 项通过。新增/更新证据覆盖偏好持久化、重置、坏数据/越界值、已有/新建表面的同步、正文和选区不变、标题栏避让、白字与旧文档 round-trip、颗粒绘制像素随参数变化且重复重绘稳定、纹理不命中鼠标、不透明回退、工具盘无笔色按钮且两种纸张仍可选择。原有 IME、拖放、焦点、撤销、横线基线和附件测试继续通过。
- **截图边界：** XCTest 的 `dark-glass-note-view-only` 和 checklist 截图可验证白字、横线、颗粒与控件绘制，已导出查看；视图绘制缓存不是 WindowServer 的跨窗口实时合成截图，不能据此宣称桌面背景模糊已视觉验收。
- **待手工确认：** 在亮/暗及高对比桌面背景上比较三种系统材质；设置中实际拖动各滑杆和颜色选择器，关闭重开与重启后外观一致；系统浅/深模式与“减少透明度”动态切换；Retina/非 Retina、多屏拖动和 resize；失焦后白字、checkbox、插图与原生红色按钮仍清晰；空闲 CPU/内存与输入性能。模糊材质不是有序的强弱等级，也不是像素半径滑杆。

## 末尾空行间距修复与标题精简

- 工具盘和两种纸张现在都隐藏标题文字，仍保留窗口名称供系统/辅助功能识别、原生标题栏拖动和纸张左上角删除按钮。新增测试覆盖两种纸张，原有立即删除测试继续通过。
- **影响范围：** 横线纸末尾空行会比正常书写行窄，后续背景横线整体上移。已用真实 NSTextView 复现：输入“测试” → Return → 输入 x → Backspace 删空最后一行；选中后 Delete、中英文与 emoji 同样受影响。重新载入多个空行也有不均匀间距。单纯直接调用 Return 不总能复现，用户截图的具体按键历史未知。
- **根因：** 原排版用 18pt 原生行高加 `lineSpacing = 7`。TextKit 2 在重建末尾空行的路径中没有计入这 7pt，虽然存储和 typingAttributes 中的段落样式仍是 7pt。实测空行基线从 59pt 变为 52pt，光标同样上移 7pt；横线忠实跟随错误的原生基线，不是单独的绘制偏移。旧测试只验证横线与基线重合，没有约束编辑前后空行间距不跳变。
- **引入时间：** `lineSpacing = 7` 来自初始提交 `f2a3dcc`（2026-10-28）；横线跟随原生基线始于 `6396621`（同日）。已验证当前修复前代码的失败，未对各历史版本或其他 macOS 版本逐一运行，不能据此断言所有系统都受影响。
- **干净修复：** 在共享排版入口 EditorProjection 中改用 `minimumLineHeight = 25`，让正常行、空行、光标和装饰共享稳定的最小行盒。不设 maximumLineHeight，图片和较高字形仍可撑开；不插入占位字符，不单独给横线补偏移，不改变正文格式或保存数据。该设置也用于待办纸，已有待办布局/图片测试继续通过。
- **验证：** 两项新间距回归在恢复旧设置时产生 26 个失败断言，修复后通过；比较实际绘制像素及原生光标矩形，覆盖末字删除、选区删除、中英文/emoji、重载连续空行、变宽/变窄、撤销/重做。完整 62 项 XCTest 通过。横线基线、跨行图片、待办与输入法既有回归全部保留；真实系统输入法候选窗口仍按手工门槛验收。
